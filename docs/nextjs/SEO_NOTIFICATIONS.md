# Public SEO and in-app notifications

Public search pages are `/`, `/tinh-nang` and `/bang-gia`. Their canonical URLs and social previews point to `https://sporthost.online`. Indexing requires both `APP_ENV=production` and the canonical origin. Preview/test instances return noindex, robots disallow all, and an empty sitemap. Root metadata remains noindex for every other page; Proxy supplies the matching HTTP header, including capability URLs. The sitemap contains no club, player, payment or invitation URLs. Homepage JSON-LD describes the website without invented reviews, ratings or user counts. Prices use the runtime subscription policy. A deployed sitemap does not imply Google has indexed the pages.

Free accounts get a paginated notification inbox at `/me/notifications` with unread count and mark-all-read. Events include invitations, host registration decisions, waitlist promotion, material schedule edits, cancellation and proof review. Events commit in the business transaction. Unique per-recipient event keys prevent duplicates. Notification content and unread counts require the current verified member link and exclude events before that link was created; unlinking or reassigning immediately revokes historical access. Account suspension is enforced at read and mutation boundaries.

Payment pages copy bank account numbers and transfer notes from the same immutable snapshot already displayed. Clipboard failures expose selectable text and an accessible status. Issued billing screens let authorized hosts copy a reminder containing the current displayed outstanding balance and payment snapshot, then send it themselves. Copying never sends a message or records payment.

Pro club owners configure RSVP lead time (1–168 hours) and issued-session debt interval (1–14 days) at `/clubs/{id}/reminders`. Both start disabled. Each recipient must separately opt in under Notifications. Reminders stay inside SportHost; no SMTP or Zalo integration is used. RSVP stops after a response, earliest registration/RSVP/start deadline, closure or cancellation. Debt reminders begin one interval after fee issuance and check actual ledger balances, excluding pending proofs. Monthly dues reminders are not included. Expired Pro, disabled settings, suspended recipients and removed links suppress new reminders. Turning reminders off remains available on Free. Event uniqueness and minimum debt cooldown prevent duplicates across concurrent jobs and settings changes.

Apply additive `v2/migrations/0005_notifications.sql` after migrations 0001–0004, using the operator database role. Grant runtime SELECT/INSERT/UPDATE/DELETE on the three new tables and USAGE/SELECT on `notifications_id_seq` as appropriate. No legacy table columns, business rows or Alembic revision are changed. Readiness requires the new tables. Older images remain compatible with additive tables; rollback must preserve all current data and uploads.

The authenticated POST `/api/internal/reminders` accepts a server-only `REMINDER_CRON_SECRET` of at least 32 random characters. Without it the endpoint rejects all requests. Each call scans up to 100 linked opted-in registrations and returns a continuation cursor. Read-only mode blocks writes. `scripts/run_sporthost_reminders.py --config <private-file>` follows pages and resumes large scans using an adjacent private state file. Its JSON configuration contains only `origin` and `secret` and must be mode 0600. The secret never belongs in cron arguments, Git, client bundles or logs. Run every 15 minutes with a per-target file lock, retaining existing unrelated cron entries. Recheck authorization, safe runtime flags and HTTP results before claiming scheduling is active.

Validation includes real PostgreSQL transaction rollback/concurrency, current-link revocation, proof/ledger behavior, Pro and opt-in boundaries, earliest deadlines, noindex isolation and browser checks on desktop/mobile. Release evidence is recorded below after deployment.
